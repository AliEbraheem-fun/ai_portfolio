Sampling and Decoding Strategies (Qwen2.5)

Next-token selection built by hand instead of through generate(): temperature, top-k, top-p, repetition penalty, and a generation loop over Qwen2.5-0.5B. Two details fail in the obvious implementation. Dividing a logit to penalise a repeat raises the probability of any token whose logit is negative, and 99.2 percent of Qwen's are. Profiling then showed a Python loop over the history costing as much as a full forward pass, hiding the KV cache speedup completely.

Prompting Methods on T-math (Qwen3)

Five in-context learning methods measured against the same 331 olympiad maths problems under one set of metrics: zero-shot, few-shot in a single message, few-shot as a dialogue, chain-of-thought, and Qwen3's built-in reasoning mode. Few-shot fixes output format (format_rate 0.656 to 1.000) and does nothing for accuracy. Chain-of-thought is the only method that moves accuracy, and only once given room: identical prompts score 0.030 format_rate at 64 new tokens and 0.840 at 512. The gain cost 38x the runtime.

Post-Training Quantization

Dynamic int8 quantization of a transformer with no retraining and no calibration set, benchmarked on two models with different weight profiles. bert-base shrinks 2.41x and runs 1.90x faster on CPU; a compact model shrinks only 1.18x and runs 1.4x slower, because just 20 percent of its weights sit in linear layers. Accuracy holds either way: 10 of 10 predictions unchanged.

Efficient Fine-Tuning: LoRA, P-tuning, QLoRA

Adapters written from scratch, then run for real on Qwen2.5-0.5B: a low-rank LoRA layer, learnable soft-prompt tokens, and a 4-bit QLoRA base, each checked by measuring peak VRAM rather than trusting the formula. Trainable parameters fall 457x while memory falls only 1.7x, because frozen weights still occupy the card. The reference LoRA initialisation turns out to be wrong: at step zero the adapter's contribution is 2.26x larger than the base layer's own output, because neither matrix is zero-initialised.

SFT on an Instruction Set: What Four Methods Cost

One dataset, one model, one set of hyperparameters, varying only the training method, with peak VRAM and seconds-per-step measured for each. Full fine-tuning of a 0.6B model at length 1024 runs out of memory on an 8 GB card, so LoRA is not an economy here but the only way to train at all. int8 quantisation then does the opposite of its billing: 5.43 GB against LoRA's 4.61, and 2.2x slower per step, because on a small base the dequantisation overhead outweighs anything saved. Gradient checkpointing was the one knob that behaved as advertised, trading 17 percent of memory for 64 percent more time.

Inference Efficiency: Prompting, Speculation, Quantization

A marketplace case study generating 100 product descriptions under a fixed quality metric, measuring latency and throughput for each optimisation. Decomposing the metric first showed 40 of its 100 points were unreachable by construction, and that the entire real headroom sat in one term. Batching gave 3.6x but the curve turns over at 16 requests as padding eats the gain. bitsandbytes NF4 halved memory and made generation 27 percent slower — the opposite of the AWQ result it is usually quoted alongside, because NF4 dequantises to bf16 on every matmul.
